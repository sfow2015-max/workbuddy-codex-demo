# 跨项目协作补充规则 V3.2

版本：V3.2｜日期：2026-10-22

本文件补充项目现有 AGENTS.md、README、任务书与专项安全政策，不替代或放宽项目专属限制。冲突时，优先遵守更具体的项目规则、用户当前指令和数据/权限 Hard Gate；不得因同步本文件而扩大业务范围、访问权限、正式部署或真实数据操作。

## 1. 项目开始前的可行性分析
新项目、首次接入外部平台/数据源、核心架构变更必须先交付简明可行性结论：目标与价值、复用方案、技术/权限/数据前提、关键失败风险、最小验证实验、投入与维护成本、停止/换路线条件。关键依赖未实测时标记“待验证”，不得写成“可行”并直接扩大开发。已有路径上的普通修复只做影响检查，避免重复立项。

## 2. 测试执行：每档只切一次设置
默认流程：**每档只切一次设置 → 本地脚本批跑 → 自动汇总 → AI 最后分析报告。** 工作流内部模型调用可以为 0。
- 执行前固定参数档位、用例矩阵、预期结果、重试上限与停止条件。
- 每档设置成功后记录实际生效值；同档重复用例由本地脚本批量执行，不逐条切换界面。
- 保留单条用例原始结果及机器可读 CSV/JSON；汇总通过/失败/跳过、成功率、耗时分布、错误分类，并能追溯到用例 ID。
- AI 在批测结束后分析汇总和必要失败日志，不要求逐条调用模型。无模型调用时明确标记为 0。
- 脚本批测、AI 逐次参与测试、人工操作、Computer Use 原生桌面测试必须分别标注。脚本批测不得称为“逐次 AI 混合测试”。
- 重试次数有限；首次失败证据不得被重试结果覆盖。达到停止条件后停止并报告。

## 3. Computer Use 最小化与短时调用
默认优先 API、CLI、本地脚本、Playwright/CDP 或项目已有自动化接口；Computer Use 默认不用，不用于常规兼容性回归。
只有真实桌面窗口/原生控件行为无法由低干扰方式验证时，才进行必要调用。调用前明确目标、步骤、预期时长和结束条件；可能抢焦点或影响用户正在进行的操作时，优先改用独立环境，无法避免明显干扰则先取得用户明确同意。
调用期间只做当前验证，不启动持续控制循环。完成、取得证据或遇阻后立即结束；检查并清理本次启动的任务、临时窗口和控制进程，不关闭用户原本打开的应用或非本次启动的进程。无法确认清理时如实报告。

## 4. 原生桌面性能样本独立
原生 Computer Use 性能对照只保留回答性能问题所必需的代表性样本，单独记录环境、样本数、计时口径和限制；不纳入常规兼容性回归通过率或覆盖率。

## 5. 验收与交付
报告必须绑定仓库、分支、被测提交 SHA、环境、运行层级、数据性质、命令、通过/失败/未运行、未覆盖项和下一步。代码存在、脚本通过、真实应用运行、安装包验证、正式安装是不同状态，不可互相替代。每批尽早提供最小可操作业务闭环；视觉精修和非必要页面可后置。

## 6. Git 与安全
开始前读取本文件、AGENTS.md、README、相关开发规范和任务/验收记录；核对分支、HEAD、工作区及远端。只提交本批相关、脱敏文件。保留已有项目规则、数据保护与 Hard Gate；不得强推、丢弃未提交修改、提交真实资料/凭据或把合并许可扩大为部署/真实数据迁移。是否创建 Draft PR、自动合并或暂停，遵守项目现有专项规则与用户对本批的具体授权。
